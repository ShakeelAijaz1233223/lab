# IT Lab Management System

A complete, offline, daily-use IT lab management application. It runs entirely in
your browser — no server, no database, no internet connection, no login.

Open `index.html` and start working.

---

## Starting data (VIP IT Labs)

This copy ships with `js/seed-data.js`, a converted snapshot of
**VIP_IT_Labs_Complete_Master_Report.xlsx** — 40 PC records (Lab 1/2/3), 4
staff systems, 15 maintenance/repair records, 13 store items and 12
purchase records.

* It loads **automatically, exactly once**, the very first time you open
  `index.html` on a browser that has no existing IT Lab data.
* If you already have any PCs, staff, maintenance, store or purchase
  records saved (e.g. you've used the app before), it changes **nothing**
  — your existing data is always left alone.
* You can always re-import it later yourself from **Backup & Restore**
  using the JSON file, or delete `js/seed-data.js` (and its `<script>` tag
  in `index.html`) if you'd rather start completely empty.
* A few fields the source spreadsheet didn't contain (staff names/
  departments, some part numbers) were left blank rather than guessed —
  see the activity log after first load for a short import note.

## Where your data lives

Everything is stored in **this browser, on this computer**, using LocalStorage.

* It survives page refreshes, browser restarts and reboots.
* It works with no internet connection.
* It does **not** sync to other computers. To move data to another machine, use
  **Backup & Restore** (JSON) or an Excel export.
* Clearing your browser's site data will erase it — export a backup regularly.

Storage keys used:

```
itlab_pcs                  itlab_store                itlab_activity_logs
itlab_staff                itlab_stock_transactions   itlab_settings
itlab_maintenance          itlab_purchases            itlab_import_history
```

All reads and writes go through one storage layer (`js/storage.js`). No module
touches `localStorage` directly.

## Monthly Archive

The sidebar's **Monthly Archive** page tracks maintenance activity by
calendar month automatically — no setup needed:

* **This month** is shown at the top as **Live**, and its totals update
  the instant you add or change a maintenance record.
* The moment the calendar rolls into a new month, the finished month
  automatically drops into the **Archived months** list below. Nothing is
  deleted — every past month stays there permanently.
* Every month, live or archived, has its own **Download** button that
  builds a fresh 3-sheet Excel workbook (Summary, full records, parts
  consumed) for exactly that month, any time you need it.

This is computed from your maintenance records directly, so it is always
in sync — there's nothing separate to keep up to date.

**Locking:** the Maintenance page itself only ever shows and accepts the
current month — August's records, for example, simply don't appear there
once September starts. Only the current month can be added, edited,
resolved or deleted. Nothing is deleted — every past month is always one
click away in Monthly Archive, both to browse (via Global Search) and to
download.

## Excel

Reports are **real `.xlsx` files** generated by SheetJS — not CSV or HTML with an
`.xlsx` extension. Every sheet has:

* a title banner (organisation, report name, generation date/time, record count),
* a bold, colour-filled header row,
* a **frozen** header row,
* **AutoFilter** applied to the real table range,
* readable column widths, borders and banded rows,
* real Excel dates (`dd-mmm-yyyy`) and real numbers — never text.

Import accepts `.xlsx` and `.xls`. The wizard reads the file, finds the header
row even when there are title rows above it, matches columns by fuzzy name, lets
you correct any mapping, then shows a full preview with valid / duplicate / error
counts and per-row messages. **Nothing is written until you confirm.** Import
modes: *Add new only* (default), *Update existing only*, *Add + update*.

## Running it

**Simplest:** double-click `index.html`. Everything works from `file://`.

**Recommended** (enables the optional service worker / installable PWA):

```bash
cd it-lab-management
python3 -m http.server 8000
# then open http://localhost:8000
```

The service worker is entirely optional — no feature depends on it, and it is
skipped silently on `file://`.

## Rules the app enforces

* Stock can never go negative. A blocked operation reports
  `INSUFFICIENT STOCK — Available: x, Requested: y` and saves nothing.
* Every quantity change writes a stock transaction. Editing or deleting a
  maintenance record reverses the stock it consumed.
* A purchase can be added to the store **once**; editing it never double-counts.
* Duplicate PCs (serial number, or PC name within a lab) are always flagged
  before saving — never silently overwritten.
* An ID coming from an imported spreadsheet is only accepted if it matches the
  application's own format (`PC-0001`); otherwise a fresh ID is issued.
* Passwords are masked (`••••••••`) with an explicit reveal, are never shown in
  list tables, and are excluded from Excel exports unless you opt in.
